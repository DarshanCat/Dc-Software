# Production Credential Rotation Procedure

Because credentials were used during development/testing, production secrets must be rotated prior to go-live.

> [!IMPORTANT]
> Do NOT perform credential rotation automatically. Execute these steps manually in the Neon and Vercel consoles.

---

## 1. Neon PostgreSQL Database Password Rotation

1. Open [Neon Console](https://console.neon.tech/) and navigate to your production project.
2. Go to **Dashboard** → **Roles / Users**.
3. Select the production database role (e.g. `neondb_owner` or main app user).
4. Click **Reset Password**.
5. Copy the newly generated connection string (`pooled` version for serverless Next.js).

---

## 2. Vercel Environment Variable Update

1. Log into [Vercel Dashboard](https://vercel.com/dashboard).
2. Open project `dc-material-management` → **Settings** → **Environment Variables**.
3. Edit `DATABASE_URL`:
   - Replace value with the new Neon connection string.
   - Select **Production** and **Preview** environments.
   - Click **Save**.
4. Trigger a new deployment:
   - Go to **Deployments** → Select latest commit → **Redeploy**.

---

## 3. Post-Rotation Infrastructure Verification

1. **Database Connection**: Access `https://dc.vijayspheroidals.in/login`. Confirm no `P1001` database connection errors occur.
2. **User Authentication**: Sign in with an admin account. Confirm authentication succeeds.
3. **Dashboard Integrity**: Confirm Live Dashboard metrics render without database query failures.
4. **DC Retrieval**: Search and open an existing Delivery Challan record. Confirm relation queries (`vendor`, `items`, `receipts`) execute cleanly.
5. **Prisma Operations**: Perform a test DC status update or draft creation to confirm write access works.

---

## 4. Real User Account Password Reset

1. Log in as an Administrator at `https://dc.vijayspheroidals.in/login`.
2. Navigate to **Admin** → **Users** (`/admin/users`).
3. For each real company user account:
   - Click **Reset Password**.
   - Copy the one-time temporary password generated by the system.
   - Communicate the temporary password securely to the user via encrypted company channel.
4. User logs in with temporary password:
   - System automatically intercepts user and forces redirect to `/change-password`.
   - User updates account with a strong permanent password meeting complexity rules.
   - User session activates with full access.
